## 执行摘要

本报告分析 Kubernetes 管理类 MCP 服务器 mcp-server-kubernetes 的一起参数注入事件：其 exec_in_pod、kubectl_patch、kubectl_logs 等工具把远程 MCP 客户端供给的值作位置操作数传给 kubectl，未拒绝以连字符开头的值，攻击者可注入 --filename 等 kubectl 标志，使 kubectl 读取服务器主机文件、绕过文件读取限制（CVE-2026-134817，CWE-88）。据 CNA（VulnCheck）公告与记录所载（机制与影响为公告所载、本文未复现；NVD 记录同源转列 CNA 描述，不构成独立复证），受影响版本为 4.2.0 之前（NVD 受影响段记 0 < 4.2.0，semver），4.2.0 修复；CNA 给出的 CVSS 4.0 向量为 AV:N/AC:L/AT:N/PR:L/UI:N/VC:H/VI:L/VA:N/SC:N/SI:N/SA:N、评分 7.1（CNA 记录所载，本稿照引、未独立复算），NVD 自身评估尚未提供（N/A）。时间分列：公开时点（CNA datePublic）为 2026-10-26——项目 v4.2.0 发布页同日已列出相关加固；CVE 记录发布（datePublished）为 2026-11-22 UTC（北京时间 11-23）；11-22 只称 CVE 记录发布日期，不称首次公开。

## 三、技术分析

### 3.1 机理：位置操作数被当作被调用程序的标志解析

本件的构造要点不在 shell 字符串拼接，而在参数列表本身：MCP 工具把远程客户端供给的值放在 kubectl 命令的位置操作数位置，kubectl 按其参数解析规则处理该值——以连字符开头的值被当作 kubectl 标志（如 --filename），而非普通操作数。于是即便每个输入仍是 argv 中一个独立参数（argv 分离），注入仍然成立：被注入的不是 shell 语法，而是被调用程序自身的标志面。防护的正确形态是二选一或并用：拒绝标志形（连字符开头）操作数值，或把操作数置于 -- 终止符之后使后续值不再作标志解析。本件 <4.2.0 两者皆未做（据公告描述段：未拒连字符开头值作位置操作数）。具体构造细节与完整可注入标志清单，一手源未逐项披露，本稿只作高层机理陈述，不写复现命令与操作细节。

### 3.2 利用条件

- 攻击者须能以远程 MCP 客户端身份接入目标 mcp-server-kubernetes（经 SSE 或 Streamable HTTP 传输）；CVSS 4.0 向量记 PR:L（需低权限）、UI:N（无需用户交互）、AV:N／AC:L／AT:N（来源：NVD 记录 metrics 段原文）。
- 目标版本 <4.2.0，且相应工具（exec_in_pod／kubectl_patch／kubectl_logs 等）把客户端值作位置操作数传给 kubectl。
- 效果以公告为准：使 kubectl 读取服务器主机文件、绕过文件读取限制；超出此范围的效果（如写入、执行）一手源未载，本稿不外推。

### 3.3 与同类事件的关系

本件与命令注入已知类别相邻但不同型：传统命令注入检查盯的是不可信输入拼入 shell 字符串且未中和；本件输入不进 shell 字符串、保持 argv 分离，注入面在被调用程序的标志解析。考卷库此前无此类别，本件立新类别「标志形位置操作数参数注入」与新缺口 SE26。

### 5.2 为何未覆盖：缺哪一类检查

本展品需要的检查形态（即考题判定要求）：对工具命令构造的参数传递摘要判定——

- **应判 fail**：不可信输入作位置操作数传递、且以连字符开头的标志形值未被拒／未以 -- 终止符隔离（本件本体）；
- **应判 pass（不误报）**：标志形操作数被拒、或操作数置于 -- 终止符之后，且有该构造自身解析行为与接线证据在卷；仅有通用做法声明、无对应证据者不判 pass（归 inconclusive）；
- **应判 inconclusive**：操作数处理证据缺失。

判定应引用被检操作数处理证据；其中 pass 一格不得以通用做法声明充数——须有该构造自身的解析行为与实际接线证据（拒收／隔离在该构造上实际生效）方可判 pass，证据不足即 inconclusive。核验钉规则面缺的正是这一类检查。相邻的 command_injection 检查回答的是「输入有没有拼进 shell 字符串并成为命令语法」：其判定序先核证据来源与字段一致性，argv_list＋untrusted 分支（argv_separated_construction）给出的是 shell 语法面的通过——满足前置条件时可通过本规则，但该通过不覆盖被调用程序的参数语义；本件恰在其自述的「不是这个模式」范围内，注入面正在参数语义，故不计覆盖，SE26 细化时须明记此分工（loop backlog SE26 条原文口径）。其余 19 插件逐件排除依据见随本报告公开版同行发布的逐件排除表（公开仓 sixu-research `reports/TB-027/evidence/plugins-exclusion-table-20.md`）：主题为授权、SQL 构造、路径钉住、模型工件等，判据入口均不接收位置操作数处理证据，不装下本展品。

### 5.3 对我方系统的同类风险映射

我方审计与工具面存在以程序方式驱动 CLI 工具的构造形态，但本稿未核我方实际部署中是否存在「远程不可信值作位置操作数传给 kubectl 或同类 CLI」构造——是否存在同型面为 UNKNOWN，不得据本节称已排查或已中招。映射结论为风险提示级（未验证）：凡把不可信值作位置操作数传递的构造，应按「拒标志形值或 -- 终止符隔离」核对，建议动作见第六节 D-04。
