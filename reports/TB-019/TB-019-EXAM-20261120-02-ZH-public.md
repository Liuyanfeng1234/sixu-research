## 执行摘要

本报告分析 AI 编码智能体 JetBrains Junie CLI 的一起写出通道路径限制失效事件：Junie CLI 经 shell 输出重定向把内容写到项目目录之外、覆写项目外文件（CVE-2026-133196）。与同批 CVE-2026-133195（文件工具直写越界）的关键区别在写出通道：本件不是文件工具直写，而是 shell 重定向——同一目录限制缺失经第二条通道成立。据 JetBrains CNA CVE 记录原件，受影响为 Junie CLI before 26.11.1、26.11.1 起不受影响（版本界线 lessThan 26.11.1、defaultStatus unaffected；记录未单列『修复版本』字段），公开日 2026-11-19（datePublished 2026-11-19T14:50:14.933Z）；CVSS 3.1 评分 5.3 与 CWE-184 为复核轮直读 CNA 记录原件（cvelistV5）所得，考卷库条目未载此两数（见第八节 G-03）。所读 CNA 记录未附 PoC，重定向的具体形态与触发构造未披露，本稿逐项标未知（见第八节）。

对 V19 规则面的覆盖判定为**未覆盖**：考卷核验钉（主链头 4fcf68b4，历史核验钉、非当前头）下，本件归 SE20 检查（v19.filesystem.unconfined_tool_write_path）跟踪，而该检查未合入主链（实取插件清单无 output_path_confinement.py）；重定向子型须在 SE20 落地时单独核，本稿不预判该检查对本子型能否判定。本件另带一条**子型分歧**：SE20 冻结口径的 observed 越界独立 fail 支以「工具写出路径」为面，shell 输出重定向通道能否装下，须在 SE20 落地复核时一并核——本稿不预判该子型在 SE20 落地后即被覆盖，判定只记未覆盖。本缺口与 EXAM-20261117-02 为同一缺口、已在 loop backlog 在队区 **SE20**，本条不重复入队，仅在 SE20 条下补记本事件与子型分歧。

## 三、技术分析

### 3.1 机理：shell 重定向是未被目录限制覆盖的第二写出通道

据考卷库考题段：编码智能体经 shell 输出重定向把内容写到项目目录之外、覆写项目外文件，写出通道不是文件工具直写而是 shell 重定向。定性要点在通道完备性：编码智能体的写出面至少有两条——文件工具直写与 shell 命令执行（重定向、管道落盘皆属之）。目录限制若只施于文件工具一面，shell 通道即成旁路：同一「写出须钉在项目目录内」的约束，须对每条写出通道分别成立才算成立。本件坐实的正是这一点——受影响的不是某个文件工具的路径校验，而是 shell 执行面的重定向目标未受同一限制。

本稿对机理的陈述以 CVE 记录描述为限：重定向的具体形态（何种 shell 构造、是否须配合特定命令）、智能体 shell 执行本身有无沙箱与确认环节、覆写的权限上下文，所据材料均未披露（G-02），故不写具体触发步骤，只按记录记「经 shell 输出重定向覆写项目外文件」为一手源主张。

### 3.2 与同批 Junie 四件的区分

同批披露的 Junie 事件共四件，写出／执行通道各不相同，覆盖判定亦不同，不合并：① CVE-2026-133195 文件工具直写越出项目目录（SE20 未覆盖，TB-018）；② 本件 CVE-2026-133196 shell 输出重定向覆写项目外文件（SE20 同缺口＋子型分歧，TB-019）；③ CVE-2026-133197 代码审查经文件名命令注入（类别命中已有命令注入检查，但构造细节未披露、记未核，TB-020 候选）；④ CVE-2026-133198 项目文件终端配置驱动执行（新类别、新缺口 SE23，TB-021）。本件与 ① 的关系最紧：同归 SE20、同为目录限制缺失，但通道不同——SE20 落地时若只按 ① 的文件工具面施工，本件通道是否被装下必须单独核，这正是考卷库记下的子型分歧，不因同缺口而自动消解。

### 3.3 利用条件

- 目标须使用受影响版本 Junie CLI（before 26.11.1）。
- 据公开向量字面：UI:R（须用户交互，次数与具体形态未披露）、PR:N（无须权限）、AC:H（复杂度高）、AV:N（向量记法，不据此断言 CLI 的网络服务形态）；影响面按向量字面记 C:N/I:H/A:N，不据此断言现场影响。被覆写文件的后续用途可放大后果——此放大链为推断、本稿标未验证。
- 攻击者诱使智能体执行带越界重定向的 shell 命令的具体构造，所据材料未披露（未知）。

### 5.1 核验方法与核验钉

- 核验钉：主链头 `4fcf68b47c7892cb3e5eded732b33046ddca85e0`（cursor/production-did-labels-e95a）——此为考卷核验时点钉，不得称当前头。规则面为该钉下 research/audit_pipeline 现头 20 插件，经 fetch.py 实取（字节存 `考卷轮（2026-11-20）实取插件树目录`，清单 `考卷轮（2026-11-20）插件清单`）。
- 检索结果：实取清单无 output_path_confinement.py（同 EXAM-20261120-01 的现头实取面，考卷库核验证据落点段）。

### 5.2 为何未覆盖：缺哪一类检查＋子型分歧

本展品需要的检查形态（即考题判定要求）：对被审对象的写出路径做目录限制判定，且判定面须含 shell 重定向通道——

- **应判 fail**：写出路径未限制在预期目录内（重定向通道），finding 须引用被检写出路径证据；
- **应判 pass（不误报）**：重定向目标经规范化后钉在项目目录内、或越界重定向被拒；
- **应判 inconclusive**：写出路径证据缺失，不冒充 fail（考题段未单列此格，按本线统一口径记）。

未覆盖有两层：其一，SE20 检查本身未合入主链，核验钉规则面没有任何一条检查对写出路径目录限制做判定（同 TB-018）；其二，子型分歧——SE20 冻结口径（EXAM-20261117-02）的 observed 越界独立 fail 支以「工具写出路径」为面，其证据形态是文件工具的写出路径；shell 重定向的写出路径藏在命令构造里，是否落入该支的证据口径，考卷库明记「须在 SE20 落地复核时一并核，不得预判覆盖」。故本稿判定止于未覆盖：既不因检查未合入而多言，也不因同缺口而预认落地后必覆盖。

### 5.3 对我方系统的同类风险映射

我方智能体日常经 shell 写文件（命令重定向落盘是常规工作方式）：凡「shell 写出目标由任务内容决定、未经目录作用域核对」的面，与本件同型，且比文件工具面更贴身。映射结论为风险提示级（未验证）：我方尚未对自有 shell 写出面做本件同型实跑核验，不得据本节称已排查；建议动作见第六节 D-04。
