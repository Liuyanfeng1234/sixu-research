# Moyan Preflight — Hybrid AI Security Auditor for AI Agents

Pre-launch security audit for AI agents, built for the **#BuildHybridAI 2026**
hackathon (Firebase AI Logic). Paste an agent specification — system prompt,
tool list, behaviour notes — and Preflight returns a ship / no-ship verdict
with findings and an auditor narrative.

## Why hybrid

Agent specs are sensitive: unreleased product behaviour, internal tooling,
data-handling policy. Sending them to a cloud model just to get a security
opinion is a bad trade. Preflight therefore runs **on-device first** and
falls back to the cloud only when it must — and says so in the UI.

1. **Deterministic pre-check (always local, no model).** A rule layer scans
   for launch-blocking patterns: embedded credentials, unrestricted shell
   access, irreversible actions without approval gates, prompt-injection
   trust of external content, cross-user shared memory, personal-data
   egress, missing audit logs, missing refusal boundaries.
2. **On-device narrative.** If Chrome's built-in AI (Gemini Nano, Prompt
   API) is available, the audit narrative is generated locally. The spec
   never leaves the browser.
3. **Cloud fallback.** Otherwise the narrative is generated by a Gemini
   model through **Firebase AI Logic** (Gemini Developer API backend),
   protected by **App Check** attestation.

## Run it locally

No build step. Serve the folder statically and open it in Chrome:

```bash
npx serve .
# or: python3 -m http.server 8080
```

The deterministic layer and the on-device path work with zero configuration.
Three built-in samples (risky / mixed / safer) are one click away in the UI.

## Enable the cloud path (Firebase AI Logic + App Check)

1. Create a Firebase project (Spark tier is enough) and enable
   **Firebase AI Logic** with the Gemini Developer API backend.
2. Register a Web app, then paste its config into `js/firebase-config.js`
   and set `FIREBASE_CONFIGURED = true`.
3. **App Check (required):** the submission build uses the debug-token flow.
   Load the app once, copy the debug token the SDK prints to the browser
   console, and register it under Firebase Console → App Check → Apps →
   Manage debug tokens. For production, switch `APPCHECK_DEBUG` off and
   provide a reCAPTCHA Enterprise site key.
4. **Cloud model (configurable):** the engine tries the ordered candidates
   in `CLOUD_MODEL_CANDIDATES` (`js/firebase-config.js`), each with a
   per-attempt timeout (`CLOUD_TIMEOUT_MS`), and uses the first that
   answers. Override at runtime with `?cloudModels=a,b` (or `?cloudModel=a`)
   in the URL, or localStorage `moyan-preflight.cloudModels` — no code edit
   needed when model availability shifts. If every candidate fails, the
   audit still completes on the deterministic layer alone and the UI labels
   it "local rules only".

## Tests

```bash
node tests/run-local-checks.mjs
```

Runs the deterministic layer against the three samples and asserts the
expected verdicts (DO NOT SHIP / FIX BEFORE LAUNCH / READY), plus an
empty-input sanity case.

## Layout

```
index.html            UI shell (+ Firebase import map, SDK 12.6.0)
styles.css
js/app.js             UI wiring
js/hybrid-engine.js   Path router: Nano -> Firebase AI Logic -> local-only
js/local-checks.js    Deterministic rule layer (pure, unit-tested)
js/samples.js         Built-in sample agent specs
js/firebase-config.js Project config + App Check + cloud-model settings
tests/                Node verification for the local layer
```

## Honesty note

The deterministic layer is heuristic (including a negation guard for specs
that explicitly forbid a pattern). Preflight is a screening tool, not a
certification; high-stakes agents still need a full human-led audit.

Path status for the bundled `moyan-preflight` project (both narrative
paths verified live on the deployed site, 2026-11-20): after the App
Check debug token was aligned with the console registration, the
earlier 401 errors
cleared and the cloud path was exercised end-to-end. The default cloud
model, `gemini-3.5-flash-lite` (Firebase AI Logic, App Check attested),
completed three consecutive live runs: the ShopBot sample returned
DO NOT SHIP (risk score 100/100, CRITICAL, 8 findings) with a
cloud-generated narrative; the SupportPilot sample returned FIX BEFORE
LAUNCH (30/100, HIGH, 2 findings) with a cloud-generated narrative; and
a ShopBot re-run reproduced the same result. Both samples were then
re-verified at the default address (no URL override) and again took the
cloud path. The on-device Gemini Nano path was verified the same day
in a Chrome where Nano was available: the status line reported
"On-device (Gemini Nano): ready", and both samples' narratives were
generated on-device (labelled "On-device · Gemini Nano" in the UI),
with verdicts identical to the cloud runs — ShopBot DO NOT SHIP
(100/100, CRITICAL, 8 findings) and SupportPilot FIX BEFORE LAUNCH
(30/100, HIGH, 2 findings). Routing is on-device first; the cloud runs
above were made separately, the same day, in a browser without Nano,
where the cloud path serves as the App Check attested fallback. The
model choice stays a runtime-configurable candidate list, and the
local verdict never depends on either narrative path.
